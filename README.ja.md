# agent-proctor

*[English](README.md) が正本です。こちらはその訳なので、内容がずれていたら英語版のほうが正しいです。*

git worktree で働くコーディングエージェントたち（iTerm2 のタブ1枚につき1つ）の
試験監督として振る舞い、どれかが手を挙げた瞬間に教えてくれる Mac アプリと CLI です。

試験監督は自分では問題を解きません。部屋を見渡して、手を挙げた人のところへ行きます。
ここでやることも同じで、タブを1枚ずつ確かめなくても、どのセッションが確認待ちで
止まっているか、どれが裏で動き続けているかが分かります。

アプリは iTerm2 と一緒に使います。サイドバーは iTerm2 のウィンドウの脇に寄り添い、
行はどれも iTerm2 のタブ1枚を指しているので、押せばそのタブへ行きます。
CLI (`proctor`) のほうは端末を選ばず、どのセッションも同じように並べます。

<p align="center">
  <img src="docs/images/sidebar-and-terminal.png" alt="iTerm2 の横に並んだサイドバー。最上部の要確認に確認待ちと完了が1件ずつ、その下に持ち主の見出しと2つのリポジトリ、3セッションが状態ごとに並び、右上には何を待っているかを伝える macOS の通知が出ている" width="880">
</p>

セッション名・コンテキストの使用率・サブエージェントの数は、タブを見ても分からない
情報です。`経過` は最後に状態が変わってからの時間で、実行中のまま長ければ考え込んで
いるか止まっているかの手がかりになります。ツールの行は、いま触っているものです。
サブエージェントは、生んだセッションの下に1体ずつぶら下がります。ブランチに
Pull Request があれば、その番号が行の先頭に付き、押すとブラウザで開きます。
色は open・merged・closed を表し、下書きは薄いままです。

```
⏳ サイドバーの空状態の表示を直す  (context: 13%)
   #128 develop · 経過: 59s
▶ Kit を層に分ける  (context: 32%)
   main · 経過: 1m  🤖2              +74 -3 ?2
   Edit: TaskStore.swift
   ├ Explore  台帳をどこで読んでいるか調べる
   │    Grep: LedgerStore · 12s
   └ general-purpose  レビュー指摘と現行コードの突き合わせ
        Read: CollectTasks.swift · 48s
```

まだ手を付けていないものは、サイドバーの最上部に固定された `要確認` のストリップに
まとまります。承認を待って止まっているもの、終わったのにまだ片付けていないもの、
落ちたのにまだ片付けていないものの3つです。確認待ちの行には何を待っているかも付きます——
`Bash: rm -rf build` のように、権限確認に出ているコマンドそのものです。確認待ちの行は
承認に答えた時点で、終わった行・落ちた行はそのタブへ行った時点で消えます。

タブへ行った時点で消えるのは既定の振る舞いで、「設定…」の `要確認` から
「完了ボタンを押したとき」に変えられます。とりあえず見ただけでは通知が残るので、
返事をしないまま置いていったものに後から気づけます。消えるのは、そのセッションが
次に動いたとき（指示を送れば動きます）か、通知の ✓ を押したときです。残るのは
ストリップだけで、下の一覧の行はタブへ行った時点で ✔ になります。一覧は
「どこで何が動いているか」、ストリップは「まだ片付けていないもの」に分かれます。

サイドバーを見ていないときは、macOS の通知が代わりに知らせます。確認待ちになった・
終わった・落ちた、その瞬間に1件出します。押すと一覧の行と同じくそのタブへ移動します。

## インストール

### Homebrew（推奨）

```bash
brew install syarihu/tap/agent-proctor
proctor sidebar
```

### ソースからビルド

```bash
scripts/create-signing-cert.sh   # 初回だけ。ローカル署名用の証明書を作る
scripts/install.sh               # /Applications に入れ、~/bin/proctor を張る
```

証明書を先に作るのは、オートメーション（Apple Events）の許可が
「バンドルID + コード署名」に紐づくためです。アドホック署名だとビルドのたびに
署名の中身が変わり、そのつど iTerm2 の操作許可を聞き直されます。

動いているアプリの上から入れ直しても、動いているほうは入れ替わりません。
`brew upgrade` も同じで、入れたあとに一度終了して開き直してください。CLI のほうは
何も要りません——叩くたびに自分が繋がっているバンドルを読みます。

初回起動時に iTerm2 の操作許可と、通知の許可を求められます。
尋ねてくるのは一度きりです。断ると二度と聞いてこないので、メニューバーから
「設定…」を開いてください。「許可」の欄に今の状態が出ていて、そこから
システム設定の該当ページへ行けます。通知を断って困るのはバナーが出ないことだけで、
サイドバーも `要確認` のストリップも今までどおり動きます。

「設定…」で「ログイン時に起動」を入れておくと、次からは自動で立ち上がります。
サイドバーの文字の大きさや幅、行のまとめ方もそこで変えられます。

## エージェントとの連携

入れただけでは一覧は空のままです。agent-proctor は台帳を読んで表示するだけの受け身の
道具で、状態を書き込むのはエージェント（Claude Code・Antigravity・Codex）の hooks の
ほうです。

繋ぎ方は環境によって変わるので（すでに hooks や statusLine を使っていれば混ぜる必要が
あります）、手順書ではなく AI に読ませて実行させる指示にしてあります。それを配るのも
proctor 自身です。

```bash
proctor setup ls        # どのエージェントの繋ぎ方があるか
proctor setup claude    # agy・codex・other も同じ
proctor setup all       # 繋ぎ方をまとめて出す
```

→ Claude Code なら会話に `! proctor setup claude` と打つだけです。
他のエージェントなら、コマンドの出力をそのまま渡してください。

入れる前に中身を読みたいときは
[`Sources/ProctorKit/Resources/ja.lproj/`](Sources/ProctorKit/Resources/ja.lproj/) にあります。

## 使い方

```bash
proctor ls              # 一覧（--all で全リポジトリ、--json で機械向け）
proctor worktree ls     # worktree の一覧。動いていないものも出る（--all、--json）
proctor skill [名前]    # 作業中の手順をエージェントに読ませる（名前なしで一覧）
proctor setup [相手]    # proctor の繋ぎ方を出す（名前なしで一覧）
proctor attach <ID>     # そのセッションのエージェント (claude / agy / codex) を開く（続きから）
proctor rm <ID>         # 台帳から1件外す（worktree には触らない）
proctor title <名前>    # いま動いているセッションに名前を付ける（空文字で外す）
proctor sidebar         # サイドバー（アプリ）を起動する
proctor --version       # 版を表示する
```

これで全部です。セッションは hooks が知らせてくれた時点で勝手に並び、エージェントが
居なくなれば勝手に消えるので、手で登録するものはありません。アプリも CLI も worktree を
作らないし消しません。読むのは台帳と `git worktree list` と `git diff` だけで、
書くのは台帳だけです。

サイドバーの行をクリックすると、そのタブが生きていればフォーカスし、閉じていれば
新しいタブで会話の続きから開きます。行にマウスを乗せると閉じるボタンが出て、押すと
一覧から外れます。worktree には触りませんし、まだ動いているセッションなら次のフックで
戻ってきます。

行はリポジトリごとにまとまっていて、そのリポジトリは持ち主（ユーザーまたは組織）
ごとにまとまっています。見出しにはそのアカウントのアイコンが付きます。見出しを押すと
畳めます。上下の段は別々に畳めて、畳んだことは次に開き直しても覚えています。畳んで
いる間は見出しに中身の内訳（`⏳1 ▶2 ⌁2`）が出るので、閉じたままでも確認待ちには
気づけます。末尾の `⌁` はセッションの乗っていない worktree の数です。状態の印とは
別の記号にして色も付けていません（worktree は状態を持たないためです）。
持ち主はディスク上の置き場所ではなく git の remote から読むので、clone の
並べ方は問いません。`gh` が入っていない・ログインしていないときは、リポジトリごとの
まとまりだけになります。

最後のセッションが終わっても、リポジトリは一覧から消えません。まだ動いている
ものの下に落ちて、見出しが畳まれた状態で残ります。残るのはこの1週間に居た場所で、
それより古いものはタブが開いているあいだだけ出ます。見出しにマウスを乗せると `+` が
出て、押せばそのリポジトリで新しいタブが開きます——昨日から触っていない場所へも
クリック1回です。残った worktree へ戻るときは、見出しを開き、worktree の畳んだ行を
開き、その行を押す、の3手になります（どちらも畳まれた状態で出るためです）。

メニューバーにも同じ内訳が出ていて、メニューを開くと同じ記号でセッションが並びます。
選べば行をクリックしたときと同じようにそのタブへ行きます。

### worktree

セッションは去りますが、worktree は残ります。最後のセッションが終わったあとディスクに
残るのは、もう誰も見ていないディレクトリです。

```bash
proctor worktree ls            # いまのリポジトリ
proctor worktree ls --all      # proctor が見たことのある全リポジトリ
proctor worktree ls --json     # 同じ内容をエージェント向けに
```

```
agent-proctor
WORKTREE  BRANCH       STATE                     DIFF   IDLE
work      feature      使用中 (2)                +1 ?1  3m
spike     spike        誰もいない                +1     2d
merged    merged-work  終わっている・消してよい         6d
```

1件ごとに、そこで動いているセッション・未コミットの変更・ブランチが取り込み済みか・
最後のコミットからどれだけ経ったかが並びます。

サイドバーでは、これがリポジトリの下に畳んだ1行として出ます
（*セッションがない worktree: 3 · 1 片付けられる*）。放置されたディレクトリの山で、
待たせているセッションを埋めてはいけないからです。

worktree を作るのも、終わったものを片付けるのもエージェントの仕事です。
その手順は proctor が同梱しています。

```bash
proctor skill ls          # どんな手順があるか
proctor skill worktree    # 1つ出す（エージェントが読んで従う）
```

本文をエージェントの設定に置かず proctor が持っているので、proctor を新しくすれば
手引きも一斉に新しくなります。何も設定しなくても、Claude Code なら会話に
`! proctor skill worktree` と打てばその場で本文が入ります。

## 設計

ロジックを CLI とアプリの両方から使えるように、`ProctorKit` を3層に分けています。
表示の都合を Kit に持ち込まないのが境界の引き方で、たとえば端末の ANSI 色は
CLI 側、SwiftUI の色はアプリ側がそれぞれ持ちます。Kit が知っているのは
「どんな状態があり、どんな記号と名前で呼ぶか」までです。

| 層 | 置くもの |
| --- | --- |
| `Model/` | データと語彙。I/O を持ちません |
| `Repository/` | 外の世界との出入り口。ここだけが台帳・git・環境を触ります |
| `UseCase/` | やりたいこと1つに1つ。判断はすべてここが持ちます |

`Localized`（人に見せる言葉）は3層のどれにも入れていません。言葉はどの層からも要る
もので、引くだけでは何も決めないためです。View（CLI の `proctor/` とアプリの
`ProctorApp/`）は UseCase を呼んで、返ってきたものを整えるだけです。

| ファイル | 役割 |
| --- | --- |
| `~/.local/state/proctor/state.json` | 台帳。全リポジトリで1つ。初回に作られます |
| `~/.local/state/proctor/avatars/` | 組織のアイコン。消して構いません（また取りに行きます） |

なぜそう決めたかは、それが効く場所のコメントに置いてあります。ここにも写すと古びるので、
書くのは片方だけにしています。
