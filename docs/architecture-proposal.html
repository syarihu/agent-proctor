Architecture Proposal for agent-proctor

階層型マルチモジュール設計草案

Feature / Domain / Data 階層型マルチモジュール構成と、具体的動詞＋引数オーバーロードの UseCase 設計を Swift（SPM）で実現します。

設計方針サマリー

本提案は、フィーチャー指向マルチモジュール構成（:feature:*, :repository:*, :usecase:*）と、「1 UseCase 1 責務・具体的動作動詞（collect / add / fetch 等）＋引数オーバーロード」 という設計思想を Swift Package Manager（SPM）に適用するものです。
Swift の「引数ラベル（Argument Labels）」を活用することで、単一責任原則を守りつつ高い可読性とテスト容易性を両立します。

UseCase の設計規律：具体的動詞 ＋ 引数オーバーロード
抽象的な execute() ではなく、具体的動作動詞（collect, add, fetch）にする！
Swift API ガイドライン準拠

1 つの UseCase クラスには 1 つの中心的な責務を与え、メソッド名は抽象的な run() や execute() ではなく、具体的な動詞（collect, add, resolve）にします。
引数や取得条件の違いは、Swift の 引数ラベル（Argument Labels） を活かしたオーバーロードで綺麗にまとめます！ 

// 1. タスク集計 UseCase の例（具体的動詞 collect + 引数ラベルによるオーバーロード）
public final class CollectTasksUseCase {
    private let ledgerRepo: LedgerRepositoryProtocol
    private let gitRepo: GitRepositoryProtocol

    public init(ledgerRepo: LedgerRepositoryProtocol, gitRepo: GitRepositoryProtocol) {
        self.ledgerRepo = ledgerRepo
        self.gitRepo = gitRepo
    }

    /// パターンA: 全リポジトリのタスクを収集
    public func collect() throws -> [CollectedTask] {
        return try collect(for: nil, itermOnly: false)
    }

    /// パターンB: 特定リポジトリに絞って収集（引数オーバーロード！）
    public func collect(for repo: String) throws -> [CollectedTask] {
        return try collect(for: repo, itermOnly: false)
    }

    /// パターンC: アプリ用に iTerm2 開閉可能なものに絞って収集（引数オーバーロード！）
    public func collect(itermOnly: Bool) throws -> [CollectedTask] {
        return try collect(for: nil, itermOnly: itermOnly)
    }

    // 内部の統合実装
    private func collect(for repo: String?, itermOnly: Bool) throws -> [CollectedTask] {
        // ... 実際の集計処理
    }
}
// 呼び出し側のコード（英語の文章のように自然に読める！）
let tasks = try taskCollector.collect()
let repoTasks = try taskCollector.collect(for: "agent-proctor")
let appTasks = try taskCollector.collect(itermOnly: true)
💡 テスタビリティの絶大なメリット： リポジトリを Protocol（インターフェース）でコンストラクタ注入（DI）できるため、単体テストでモックを簡単に差し替えられるようになります！

Package.swift の完成コード例
// swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "proctor",
    defaultLocalization: "en",
    platforms: [.macOS(.v13)],
    targets: [
        // -------------------------------------------------------------
        // 1. 基盤層 (Core / Resources / Utility) - 最下層・他へ依存しない
        // -------------------------------------------------------------
        .target(name: "Model", path: "Sources/Model"),
        .target(name: "Utility", path: "Sources/Utility"),
        .target(name: "Resources", resources: [.process("Resources")], path: "Sources/Resources"),
        .target(name: "DesignSystem", dependencies: ["Resources", "Model"], path: "Sources/DesignSystem"),

        // -------------------------------------------------------------
        // 2. リポジトリ層 (データソースごとに小分け)
        // -------------------------------------------------------------
        .target(name: "RepositoryLedger", dependencies: ["Model", "Utility"], path: "Sources/Repository/Ledger"),
        .target(name: "RepositoryGit", dependencies: ["Model", "Utility"], path: "Sources/Repository/Git"),
        .target(name: "RepositoryGitHub", dependencies: ["Model", "Utility"], path: "Sources/Repository/GitHub"),

        // -------------------------------------------------------------
        // 3. ユースケース層 (ドメイン・機能ごとに小分け！)
        // -------------------------------------------------------------
        .target(
            name: "UseCaseTask",
            dependencies: ["Model", "RepositoryLedger", "RepositoryGit", "RepositoryGitHub"],
            path: "Sources/UseCase/Task"
        ),
        .target(
            name: "UseCaseSession",
            dependencies: ["Model", "RepositoryLedger"], // Git不要で最速！
            path: "Sources/UseCase/Session"
        ),
        .target(
            name: "UseCaseWorktree",
            dependencies: ["Model", "RepositoryGit"],
            path: "Sources/UseCase/Worktree"
        ),
        .target(
            name: "UseCaseNotice",
            dependencies: ["Model", "RepositoryLedger"],
            path: "Sources/UseCase/Notice"
        ),

        // -------------------------------------------------------------
        // 4. フィーチャー層 (:feature:*) - 必要な UseCase だけを注入！
        // -------------------------------------------------------------
        .target(
            name: "FeatureSidebar",
            dependencies: ["UseCaseTask", "UseCaseWorktree", "UseCaseNotice", "DesignSystem", "Resources", "Model"],
            path: "Sources/Feature/Sidebar"
        ),
        .target(
            name: "FeatureMenuBar",
            dependencies: ["UseCaseNotice", "DesignSystem", "Resources", "Model"],
            path: "Sources/Feature/MenuBar"
        ),
        .target(
            name: "FeatureSettings",
            dependencies: ["DesignSystem", "Resources"], // UseCase 依存ゼロで完全自律！
            path: "Sources/Feature/Settings"
        ),

        // -------------------------------------------------------------
        // 5. アプリ本体 & CLI (:app / :cli)
        // -------------------------------------------------------------
        .executableTarget(
            name: "ProctorApp",
            dependencies: ["FeatureSidebar", "FeatureMenuBar", "FeatureSettings", "UseCaseSession"],
            path: "Sources/App"
        ),
        .executableTarget(
            name: "proctor",
            dependencies: ["UseCaseSession", "UseCaseTask", "UseCaseWorktree", "Resources", "Model"],
            path: "Sources/CLI"
        )
    ]
)

導入のステップ（移行手順）
1

ディレクトリの再配置

Sources/Feature/, Sources/UseCase/, Sources/Repository/ などのディレクトリを作成し、既存ファイルを移動します。

2

Package.swift の更新

定義例に従い、各ターゲットに path: "Sources/..." を指定して依存関係を宣言します。

3

UseCase のクラス化 & メソッド命名

静的 enum から final class にリファクタリングし、具体的な動詞（collect, record）と引数オーバーロードを実装します。

4

ビルドスクリプト更新 & baseline 検証

scripts/build-app.sh のリソースコピーパスを Sources/Resources に合わせ、scripts/baseline.sh で挙動が一致することを確認します。
